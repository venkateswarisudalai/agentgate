The problem

AI agents have write access to production. Nothing watches them.

01

Prompts aren’t controls

Telling an agent “don’t drop the prod DB” in a system prompt fails roughly 5% of the time. That 5% is an incident.

02

IAM was built for humans

RBAC, scoped tokens, and review queues assumed deterministic actors. Agents are non-deterministic, with derived intent and shifting credentials.

03

You can’t audit what you can’t see

When an agent does something it shouldn’t, the trail is scattered across logs, prompts, and tool calls — if it exists at all.

How it works

Three lines of code. No new infrastructure.

  1. 1

    Install the SDK

    Drop @agentgate/sdk into your agent. Point it at the control plane (self-hosted or cloud).

  2. 2

    Wrap dangerous actions

    Before any destructive call — refund, delete, deploy — call requireApproval(). The agent pauses until a decision arrives.

  3. 3

    Decide once, reuse forever

    Approve in the dashboard or Slack. Write a policy so it auto-decides next time. The audit log builds itself.

agent.ts 
import { AgentGate } from "@agentgate/sdk";

const gate = new AgentGate({
  baseUrl: "https://gate.acme.com",
  agent: "support-bot",
});

const decision = await gate.requireApproval({
  action: "db.delete",
  reason: "Purging old test users",
  metadata: { table: "users", rows: 1_847 },
});

if (decision.approved) runIt();
else stop(decision.reason);
