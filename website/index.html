The problem

Prompts aren't a security boundary.

In 2026, agents hold real production credentials — they push code, issue refunds, run infra commands. Telling an agent "don't" fails about 5% of the time, and that 5% is an incident. IAM and RBAC assumed a human or a stable service. Agents are neither.

🗝️

Shifting credentials

Agents derive intent at runtime and borrow whatever access they're handed. Static roles don't model that.

🎲

Non-deterministic

The same prompt can produce a safe action or a destructive one. You can't allow-list a probability.

🕳️

No record

When an agent acts in prod, most teams have no audit trail and no way to stop it mid-action.

How it works

It sits where intent becomes action.

agentgate wraps the agent's tool calls. Your MCP client connects to the gate instead of the server. Everything is forwarded — except risky calls, which it intercepts, classifies, and gates.

⚖️

Policy

Rules allow, deny, require approval, or quarantine an agent — by agent, action, and condition.

✋

Human-in-the-loop

Destructive calls freeze and wait. A human approves or denies from the dashboard, terminal, or phone.

🧾

Audit

Every call — allowed, denied, pending — is recorded. A flight recorder for what your agents did.

What's inside

One control plane, many ways in.

mcp-gate

Wraps any MCP server. The zero-code gateway — point your client at it.

claude-code-hook

Gates Claude Code's Bash, Edit and Write calls before they run.

control-plane

The server + dashboard: policy engine, live audit log, agent roster.

sdk

One primitive — requireApproval() — to gate custom actions in your own code.

cli

Approve or deny agent actions without leaving your terminal.

pkg-scan

Supply-chain risk signals on packages an agent tries to install.
